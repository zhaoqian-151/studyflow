# 求职展示指南

## 项目定位

推荐名称：**StudyFlow：基于 FastAPI 的 AI 学习管理与知识库助手**。

它的价值在于把用户数据、模型工作流、知识检索和可操作的前端串成业务闭环。相比单一聊天窗口，更容易说明你如何设计数据模型、划分权限、处理异常、验证写入和落地 AI 功能。

代码使用 AI 辅助完成；在简历和面试中按你的实际参与程度表述。至少要自己运行、阅读关键实现、接入真实模型并做一次有意义的修改，能够解释主要取舍。

## 可按实际情况使用的简历描述

**AI 应用开发方向：**

- 使用 Python、FastAPI、SQLAlchemy 构建学习管理与知识库应用，形成计划、任务、专注记录和学习统计闭环。
- 实现文档解析、带重叠分块、BM25 + PostgreSQL pgvector / RRF 混合检索，建立 HNSW 余弦索引并按用户隔离查询，将来源注入上下文，通过 SSE 输出带引用回答。
- 编排「读取学习数据 → 结构化生成 → Pydantic 校验 → 用户确认 → 事务写入」规划流程，保存工具步骤，并提供模型失败降级和请求额度控制。

**全栈开发方向：**

- 开发响应式学习工作台与 FastAPI REST API，覆盖账户、计划任务、专注计时、知识库和统计页面。
- 设计 Cookie 会话与用户数据隔离；使用唯一约束、条件更新与事务解决每日打卡、专注记录和规划确认的重复写入问题。
- 使用 WebSocket 实现登录用户群聊，支持消息持久化、在线人数、断线重连与基础限流，并通过 API 和真实浏览器回归验证核心流程。
- 引入 Alembic 结构迁移，编写带 SQLite 快照备份、事务复制、逐表校验和与向量精度检查的数据迁移工具；在隔离 PostgreSQL 测试库验证业务与迁移流程。

可以说明已实现 PostgreSQL、pgvector HNSW 与 Alembic，但不要写「React / Vue」「LangGraph 多智能体」「Redis 分布式」「自动长期记忆」「生产高并发」：当前没有这些能力。不要用 8 条手写评测的 100% 结果宣传通用检索准确率，更不要虚构用户规模、QPS 或提升百分比。

## 五分钟演示顺序

1. 注册或登录，载入示例计划与资料，说明界面所有业务数据均来自 API。
2. 勾选任务，展示计划进度与概览统计同步变化。
3. 选择「1 分钟体验」，刷新页面，展示计时恢复；一分钟后查看累计时长。
4. 在知识库提问「FastAPI 中如何隔离不同用户的数据」，展开来源并阅读全文。无密钥时明确说明展示的是检索摘录。
5. 输入学习目标，查看运行步骤和计划草稿，确认后到计划页查看新增任务。
6. 用两个浏览器上下文登录不同账户，演示私有计划隔离与公共群聊广播。
7. 展示测试结果、失败降级测试和代码中的数据库约束。

如果演示 AI 岗位，提前接入真实的对话和 Embedding 模型，检查供应商兼容性、真实来源引用与错误提示。不要在现场演示才第一次配置密钥。

## 应该能够回答的面试问题

| 问题 | 代码中的答案线索 |
| --- | --- |
| 为什么用 Cookie 会话而非 JWT？ | 便于撤销、服务端控制有效期，同源部署无需把 token 暴露给前端 JavaScript |
| 如何防止越权读取？ | 当前用户依赖 + 所有权检查，检索按 user_id 过滤 |
| 连点确认会不会多出两份计划？ | 状态条件 UPDATE + 事务；并发竞争返回 409，顺序重复返回原 plan_id |
| 前端改倒计时会不会多记学习时长？ | 服务端持有 started_at 和 minutes，完成前检查服务端时钟 |
| 为什么需要 RRF？ | 避免直接相加不可比的 BM25 分值和余弦相似度，通过名次融合 |
| 分块为什么重叠？ | 减少边界割裂，但会增加索引体积和重复上下文 |
| 模型失败怎么办？ | 规划明确降级；回答流显示错误并保留来源；索引失败回滚 |
| 如何验证 AI 输出？ | Pydantic 校验结构、数量与时长；这不等于验证语义正确 |
| 引用就代表可信？ | 不代表；当前未自动验证每个生成断言，需要真实质量评测 |
| 如何扩容？ | SQL / 向量索引、后台任务、Redis 广播与限流、异步 I/O、迁移和压测，按瓶颈逐步推进 |

## 建议你亲手完成的下一阶段

1. 接入真实供应商，记录一次正常调用与一次失败恢复的调试过程。
2. 收集至少数十条真实学习问题，人工标注相关片段，比较 BM25 与混合检索的效果和耗时。
3. 在已有文档范围问答和手动重建索引基础上，亲手增加一项功能，例如后台索引任务、按资料组检索或导出学习周报。
4. 如果主投全栈，可把当前页面拆为 React / Vue 组件，保持 FastAPI API 不变，并补上前端状态与类型契约。
5. PostgreSQL / pgvector 与 Alembic 已实现；下一步用更大语料验证 HNSW 召回与延迟，并为 BM25 引入倒排检索，完成真实性能测试。
